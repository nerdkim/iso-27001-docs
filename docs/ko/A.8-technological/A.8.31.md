# A.8.31 개발, 시험, 운영 환경 분리 (Separation of development, test and production environments)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제 (Technological) |
| 통제 | A.8.31 개발, 시험, 운영 환경 분리 |
| 통제 유형(참고) | 예방적 (Preventive) |
| 보안 속성(참고) | 기밀성, 무결성, 가용성 |
| ISMS-P 대응 | 2.8.3 시험과 운영 환경 분리 |
| 2013 대응 | 12.1.4 (개발/시험/운영 시설의 분리) |

## 통제 목적

개발/시험/운영 환경을 물리적 또는 논리적으로 분리하여, 검증되지 않은 코드나 설정 변경이 통제 절차를 거치지 않고 운영 서비스에 반영되거나 운영 데이터가 보안 수준이 낮은 하위 환경으로 유출되는 것을 예방하기 위한 통제입니다. 환경 간 경계와 이관 절차를 명확히 함으로써 운영 시스템의 무결성 및 가용성을 보호하고, 개발/시험 과정에서 발생하는 실수나 무단 변경이 운영에 미치는 영향을 최소화합니다. 온프레미스뿐 아니라 클라우드/컨테이너/CI-CD 등 자동화된 배포 환경에서도 동일한 분리 원칙이 일관되게 유지되어야 합니다.

## 주요 확인사항

1. 개발/시험/운영 환경이 물리적 또는 논리적(네트워크/시스템/계정)으로 분리되어 있는가?
2. 환경 간 소프트웨어 및 변경사항 이관 절차(승인, 변경관리 연계, 무결성 검증, 롤백)가 정의되고 시행되는가?
3. 개발/시험 환경에서 운영 데이터의 사용이 통제되며, 부득이한 경우 마스킹/가명화 및 별도 승인이 이루어지는가?
4. 환경별 접근권한이 분리되고, 개발자의 운영환경 직접 접근이 최소화/통제되는가?
5. 운영환경에 컴파일러/개발도구/소스코드 등 불필요한 개발 요소가 제거되어 최소 구성으로 유지되는가?
6. 클라우드/컨테이너/IaC/CI-CD 등 자동화 배포 환경에서도 환경 분리와 계정/시크릿 분리가 적용되는가?

## 이행 지침

- 개발/시험/운영 환경을 물리적으로 분리하거나, 별도의 네트워크 세그먼트/VPC/구독/프로젝트/네임스페이스 및 계정으로 논리적으로 분리합니다.
- 하위 환경에서 운영 환경으로의 이관은 변경관리와 연계하여 승인/기록하고, 배포 산출물의 무결성 검증(서명, 아티팩트 검증) 및 롤백 절차를 마련합니다.
- 개발자의 운영환경 직접 접근을 원칙적으로 차단하고, 필요 시 최소 권한/한시적 권한 부여 및 특권접근관리(PAM)를 통해 통제/기록합니다.
- 운영 데이터를 시험 목적으로 사용하지 않는 것을 원칙으로 하며, 불가피한 경우 마스킹/가명화 처리 후 책임자 승인을 거쳐 제한적으로 사용합니다.
- 환경을 명확히 식별할 수 있도록 접속 배너/화면 색상/호스트 네이밍 규칙 등을 적용하여 운영-시험 간 오조작을 방지합니다.
- 운영환경에서는 컴파일러/디버깅 도구/개발용 계정/소스코드 등 불필요한 요소를 제거하여 공격 표면을 최소화합니다.
- 클라우드/IaC/CI-CD 파이프라인에서도 환경별로 계정, 네트워크, 시크릿/자격증명, 파이프라인 권한을 분리하여 교차 접근을 차단합니다.

- ISO 27001 본문 연계: 8.1(운영 계획 및 통제), 6.1(위험 및 기회를 다루는 조치)
- 인접 Annex A: A.8.32(변경 관리), A.8.33(시험 정보), A.8.25(보안 개발 생명주기), A.8.4(소스코드 접근 통제), A.8.9(구성 관리), A.8.2(특권 접근권한), A.8.3(정보 접근 제한)
- ISMS-P 대응: 2.8.3 시험과 운영 환경 분리 (연계: 2.8.4 시험 데이터 보안, 2.8.6 운영환경 이관, 2.9.1 변경관리, 2.5.5 특수 계정 및 권한 관리)
- 2013 대응: 12.1.4 (개발/시험/운영 시설의 분리)

## 증적자료

- 개발/시험/운영 환경 분리 정책/절차 및 네트워크 구성도
- 환경별 접근권한 부여 목록 및 접근권한 검토 기록
- 환경 간 이관/배포 승인 기록(변경관리 연계) 및 롤백 절차 문서
- 시험 데이터 마스킹/가명화 처리 내역 및 사용 승인 기록
- 클라우드/IaC 환경 분리 설정(계정/VPC/네임스페이스/시크릿 분리) 증적
- 운영환경 최소 구성 점검 결과(컴파일러/개발도구/소스코드 제거 확인)

## 부적합 사례

- 개발/시험/운영이 동일한 서버 또는 동일 네트워크 세그먼트에서 분리 없이 운영되는 경우
- 개발자가 운영 데이터베이스/서버에 상시 접근 권한을 보유하고 있는 경우
- 운영 데이터를 마스킹/가명화 없이 시험 환경으로 복제하여 사용하는 경우
- 변경관리 승인 없이 개발자가 소스코드나 설정을 운영환경에 직접 반영(핫픽스)하는 경우
- 운영환경에 컴파일러/디버깅 도구/소스코드가 남아 있어 공격 표면이 확대된 경우
- 클라우드에서 개발과 운영이 동일 계정/VPC를 공유하거나 시크릿/자격증명을 공용으로 사용하는 경우
