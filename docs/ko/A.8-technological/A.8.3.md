# A.8.3 정보 접근 제한 (Information access restriction)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제 (Technological) |
| 통제 | A.8.3 정보 접근 제한 |
| 통제 유형(참고) | 예방적 (Preventive) |
| 보안 속성(참고) | 기밀성 / 무결성 |
| ISMS-P 대응 | 2.6.3 응용프로그램 접근 |
| 2013 대응 | A.9.4.1 |

## 통제 목적

접근통제 정책에 따라 정보 및 응용시스템 기능에 대한 접근을 제한하여, 인가된 사용자/프로세스가 업무상 필요한 데이터와 기능에만 접근하도록 보장하는 통제입니다. 최소권한 및 알 필요성(need-to-know) 원칙을 시스템/응용/데이터 계층에서 실제로 구현하여, 인가받지 않은 열람, 변경, 유출을 예방하는 것을 목적으로 합니다.

## 주요 확인사항

1. 정보 및 응용시스템 기능에 대한 접근이 접근통제 정책과 직무별 권한 정의(역할/메뉴/기능/데이터 범위)에 따라 제한되고 있는가?
2. 최소권한 및 알 필요성 원칙에 따라 사용자/역할별로 접근 가능한 데이터와 기능이 구분되어 있는가?
3. 화면/메뉴/기능/레코드/필드 수준에서 인가되지 않은 접근이 차단되고, 결과의 조회/출력/다운로드 범위가 통제되는가?
4. 민감한 기능(대량조회, 다운로드, 관리자 메뉴 등)에 대한 접근이 별도로 제한/승인되고 기록되는가?
5. 응용프로그램이 데이터베이스/파일/API 등 후단 자원에 접근할 때 최소권한 계정으로 동작하도록 구성되어 있는가?

## 이행 지침

- 접근통제 정책을 근거로 역할 기반(RBAC) 또는 속성 기반(ABAC) 권한 모델을 정의하고, 메뉴/기능/데이터별 권한 매트릭스를 문서화합니다.
- 서버 측(백엔드)에서 매 요청마다 인가를 검증하여, 화면 숨김/비활성화에만 의존하지 않도록 합니다(직접 URL/API 호출을 통한 우회 차단).
- 조회 결과의 대량 출력/다운로드/복사에 대한 제한(건수 제한/마스킹/워터마크/승인)을 적용합니다.
- 응용-DB 연결은 공유 관리자 계정 대신 최소권한 서비스 계정을 사용하고, 필요한 테이블/뷰/프로시저로 접근을 한정합니다.
- 권한 부여/변경/회수 절차와 주기적 접근권한 검토(A.5.18)를 연계하고, 직무분리(A.5.3)로 위험한 권한 조합을 방지합니다.
- 접근 인가 및 거부 이벤트를 로그로 남기고(A.8.15) 모니터링과 연계합니다.

## 관련 통제 및 속성

- ISO 27001 본문 연계: 8.1(운영 계획 및 통제), 6.1(위험 대응), 9.1(모니터링, 측정, 분석 및 평가)
- 인접 Annex A: A.5.15(접근통제), A.5.18(접근권한), A.5.3(직무분리), A.8.2(특권 접근권한), A.8.4(소스코드 접근), A.8.5(보안 인증), A.8.18(특권 유틸리티 프로그램 사용)
- ISMS-P 대응: 2.6.3 응용프로그램 접근 (관련: 2.6.2 정보시스템 접근, 2.6.4 데이터베이스 접근)
- 2013 대응: A.9.4.1(정보 접근 제한)

## 증적자료

- 접근통제 정책 및 직무별/역할별 권한 매트릭스
- 응용시스템 메뉴/기능 권한 설정 화면 및 사용자-역할 매핑 현황
- 서버 측 인가 검증 로직/설정(예: 권한 체크 코드, 정책 파일)
- 대량조회/다운로드 제한 및 승인 기록
- 응용-DB 서비스 계정 권한 부여 내역 및 접근권한 검토 결과

## 부적합 사례

- 화면에서 메뉴만 숨겨두고 서버 측 인가 검증이 없어 직접 URL/API 호출로 인가되지 않은 기능/데이터에 접근 가능한 경우
- 직무와 무관하게 광범위한 조회/다운로드 권한이 기본 부여되어 최소권한 원칙이 지켜지지 않는 경우
- 응용프로그램이 과도한 권한을 가진 DB 관리자 계정으로 접속하여 모든 테이블에 접근 가능한 경우
- 대량 개인정보 조회/다운로드에 대한 제한, 승인, 기록이 없는 경우
- 권한 매트릭스가 최신화되지 않아 실제 부여 권한과 정의된 권한이 불일치하는 경우
