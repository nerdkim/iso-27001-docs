# A.8.10 정보 삭제(Information deletion)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제(Technological controls) |
| 통제 | A.8.10 정보 삭제 |
| 통제 유형(참고) | 예방적(Preventive) |
| 보안 속성(참고) | 기밀성 |
| ISMS-P 대응 | 2.9.7 정보자산의 재사용 및 폐기 |
| 2013 대응 | 2022 신규 |

## 통제 목적

정보 삭제는 더 이상 필요하지 않은 정보를 정보시스템, 저장장치, 저장매체에서 확실하게 지워 불필요한 노출을 예방하도록 요구하는 통제입니다. 보유기간이 지난 데이터를 방치하면 유출 시 피해 범위가 커지고 법적/계약적 보유 제한을 위반할 수 있으므로, 삭제 대상과 방법을 정하고 삭제가 실제로 이루어졌음을 검증하여 기밀성을 보장하는 것이 목적입니다.

## 주요 확인사항

1. 정보 유형별 보존/삭제 시점과 법적 보존 예외를 정하고, 근거가 끝난 정보를 식별하여 삭제하는 절차가 있는가?
2. 개별 기록 삭제와 매체 전체 삭제/파기를 구분하고, 시스템/매체/클라우드 서비스의 기능과 책임 범위에 맞는 방법을 정하는가?
3. 삭제 수행 결과와 방법의 적합성을 검증하고 확인 가능한 범위, 잔존 사본 및 검증 한계를 기록하는가?
4. 외부 위탁/클라우드 환경에서 계약 종료 또는 목적 달성 시 수탁자가 보유/처리하는 정보가 삭제되도록 계약/절차에 반영하고, 그 이행을 확인하는가?
5. 백업본, 스냅샷, 아카이브, 파생 사본 등 동일 정보의 모든 복제본이 삭제 범위에 포함되는가?

## 이행 지침

- 정보 유형별 보존 근거와 삭제 조건을 정하고 만료 정보를 주기적으로 처리합니다. 법적 보존 명령 등 적용 예외가 있으면 범위, 사유, 책임자와 재검토 시점을 기록하고 목적 외 사용을 제한합니다.
- 개별 데이터는 애플리케이션/서비스의 삭제 기능과 사본 관리 절차로 처리하고, 매체 전체의 재사용/폐기는 A.7.14에 따라 수행합니다. SSD에 일반 덮어쓰기를 일괄 적용하거나 공유 클라우드 저장장치를 고객이 직접 덮어쓸 수 있다고 가정하지 않습니다. 공급자 기능과 계약상 책임을 확인합니다.
- 암호학적 삭제는 대상 데이터의 전체 암호화 이력과 관련 키 사본의 제거 가능성을 확인한 뒤 적용합니다. 키의 복구/에스크로/백업 사본과 별도 평문 또는 다른 키로 암호화된 사본을 식별하며, 키 하나의 삭제로 모든 사본이 사라졌다고 판단하지 않습니다.
- 삭제 로그, 서비스 상태, 공급자 증빙과 가능한 표본 검증으로 수행 결과를 확인합니다. 매체와 서비스에 따라 확인 가능한 범위가 다르므로 검증 한계와 미처리 항목을 기록하고 추적하며, 로그나 확인서만으로 절대적 복구 불가능성을 주장하지 않습니다.
- 클라우드/외부 위탁 계약에 계약 종료 시 데이터 반환 또는 삭제 의무, 삭제 증빙 제출을 명시하고 이행 여부를 점검합니다.
- 백업, 스냅샷, 복제본, 로그와 임시 파일의 위치를 파악합니다. 즉시 개별 삭제가 어려운 사본은 적용 의무에 맞는 보존/만료 기한과 사용 제한을 정하고 책임자를 지정합니다. 복구 시 삭제 대상이 다시 사용되지 않도록 재삭제 절차를 적용하며 만료 처리를 확인합니다.

## 관련 통제 및 속성

- ISO 27001 본문 연계: 7.5(문서화된 정보), 8.1(운영 계획 및 통제)
- 인접 Annex A: A.8.11(데이터 마스킹), A.8.12(데이터 유출 방지), A.7.10(저장 매체), A.7.14(장비의 안전한 폐기 또는 재사용), A.5.34(프라이버시 및 개인식별정보 보호)
- ISMS-P 대응: 2.9.7 정보자산의 재사용 및 폐기(개인정보는 3.4.1 개인정보 파기 병행)
- 2013 대응: 2022 신규(2013년 판에 대응 통제 없음)

## 증적자료

- 정보 보유/삭제 정책 및 절차서, 정보 유형별 보유기간 표
- 보유기간 경과 데이터 식별 및 삭제 실행 기록(삭제 로그, 삭제 대장)
- 저장매체 안전 삭제/파기 확인서 또는 파기 증명서
- 암호화 삭제 시 키 파기 기록 및 키 관리 대장
- 클라우드/위탁 계약의 삭제 조항 및 계약 종료 시 삭제 증빙
- 삭제 완전성 검증 결과(복구 시도 결과, 샘플 점검 기록)

## 부적합 사례

- 보유기간이 지난 데이터가 삭제 기준 없이 장기간 방치되어 운영 시스템에 그대로 남아 있는 경우
- SSD 또는 클라우드의 실제 삭제 기능과 잔존 사본을 확인하지 않고 단순 파일 삭제만으로 필요한 삭제가 완료되었다고 처리한 경우
- 운영본 삭제 후 남은 백업/스냅샷/로그가 보존 근거, 사용 제한, 만료 및 복구 시 재삭제 관리에서 누락된 경우
- 위탁/클라우드 계약 종료 후 수탁자가 보유한 데이터의 삭제 여부를 확인하지 않고 증빙도 확보하지 않은 경우
- 삭제를 완료했다고 보고했으나 처리 결과, 범위와 한계를 확인할 증빙이 없어 검증할 수 없는 경우
