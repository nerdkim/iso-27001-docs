# A.8.24 암호화 사용 (Use of cryptography)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제 (Technological) |
| 통제 | A.8.24 암호화 사용 |
| 통제 유형(참고) | 예방적 (Preventive) |
| 보안 속성(참고) | 기밀성 / 무결성 / 가용성 |
| ISMS-P 대응 | 2.7.1 암호정책 적용 |
| 2013 대응 | A.10.1.1, A.10.1.2 |

## 통제 목적

암호화 사용 통제는 정보의 기밀성, 무결성, 진정성을 보호하기 위해 조직이 암호 기술을 언제, 어디에, 어떤 강도로 적용할지 정책으로 정의하고 일관되게 운영하도록 요구합니다. 암호는 알고리즘 선택만으로 완결되지 않으며, 키 생성부터 폐기까지의 생애주기 전반과 법적/규제적 제약(국내 승인 알고리즘, 수출입 규제, 계약상 요구 등)을 함께 고려해야 실질적 보호 효과를 얻을 수 있습니다. 검증되지 않은 자체 알고리즘과 취약한 설정을 배제하고, 위험 수준에 비례한 암호 강도를 유지하며, 시간이 지나 알고리즘이 노후화될 때 교체할 수 있는 대비를 갖추는 것이 목적입니다.

## 주요 확인사항

1. 암호 사용에 관한 조직 차원의 정책이 수립되어 적용 대상(저장 데이터, 전송 데이터, 인증정보 등)과 승인 알고리즘/최소 키 길이 기준이 명시되어 있는가?
2. 사용 중인 암호 알고리즘과 키 길이가 현행 권고 수준을 충족하며, 취약하거나 폐기 예정인 알고리즘(구형 해시/블록암호 등)이 식별되고 대체 계획이 마련되어 있는가?
3. 키 생성/배포/저장/사용/교체/폐기/복구 등 키 생애주기 전 과정에 대한 관리 절차와 책임이 정의되어 있는가?
4. 개인정보/인증정보 등 중요 정보가 저장 시 및 전송 시 암호화되며, 예외 적용 시 승인 및 근거가 기록되는가?
5. 암호 관련 법적/규제 요구사항(국내 승인 알고리즘, 수출입 규제, 계약상 요구)을 식별하고 준수하는가?
6. 암호 모듈/키 저장소(HSM, KMS 등)에 대한 접근이 통제되고 관련 활동이 로깅/검토되는가?

## 이행 지침

- 암호 사용 정책에 적용 범위, 승인 알고리즘 목록, 최소 키 길이, 운영 모드, 예외 승인 절차를 명문화하고 위험평가 결과와 연계하여 적용 대상의 우선순위를 정합니다.
- 저장 데이터 암호화(디스크/데이터베이스/파일)와 전송 데이터 암호화(TLS 등 안전한 프로토콜/버전)를 구분해 적용하고, 취약 프로토콜(구형 TLS)과 취약 암호군을 비활성화합니다.
- 키는 안전한 난수원으로 생성하고 HSM 또는 전용 키관리시스템(KMS)에 보관하며, 평문 키를 소스코드/설정파일/로그에 저장하지 않습니다.
- 키 교체 주기, 손상 의심 시 즉시 폐기/재발급, 분실 대비 백업/에스크로 절차를 정의하고, 키 취급에 이중통제 및 직무분리를 적용합니다.
- 검증된 표준 알고리즘과 신뢰할 수 있는 라이브러리만 사용하고 자체 개발 암호를 금지하며, 사용 중인 라이브러리 버전과 알려진 취약점을 지속 관리합니다.
- 알고리즘/키 강도의 노후화에 대비한 암호 민첩성(crypto-agility)을 설계에 반영하고, 정책과 적용 현황을 정기적으로 재검토하여 갱신합니다.

## 증적자료

- 암호 사용 정책/지침 문서 및 승인 알고리즘/최소 키 길이 기준표
- 저장/전송 암호화 적용 현황표(대상 시스템별 알고리즘/키 길이/프로토콜 버전)
- 키 관리 절차서 및 키 생애주기 대장(생성/교체/폐기 이력)
- HSM/KMS 접근권한 목록 및 접근/작업 로그
- TLS 설정 점검 결과(취약 버전/암호군 비활성화 증적) 및 취약점 점검 보고서
- 암호 관련 법규/규제 준수 검토 기록

## 부적합 사례

- 암호 사용 정책은 있으나 적용 대상 및 최소 키 길이 기준이 없어 시스템마다 제각각으로 암호가 적용된 경우
- 데이터베이스에 개인정보가 평문으로 저장되거나 취약한 해시(단순 MD5/SHA-1)로 저장된 경우
- 운영 서버에서 구형 TLS(1.0/1.1)와 취약 암호군이 여전히 활성화되어 있는 경우
- 암호키가 애플리케이션 소스코드/설정파일/저장소에 평문으로 하드코딩된 경우
- 키 교체 주기가 정의되지 않아 수년간 동일 키를 사용하고, 손상 시 폐기/재발급 절차가 없는 경우
- 검증되지 않은 자체 개발 암호 알고리즘을 사용하거나 국내 승인 알고리즘 요구를 충족하지 못한 경우
