# A.8.5 보안 인증 (Secure authentication)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제 (Technological) |
| 통제 | A.8.5 보안 인증 |
| 통제 유형(참고) | 예방적 (Preventive) |
| 보안 속성(참고) | 기밀성 / 무결성 |
| ISMS-P 대응 | 2.5.3 사용자 인증 |
| 2013 대응 | A.9.4.2 |

## 통제 목적

접근하려는 정보 및 시스템의 중요도와 위험 수준에 부합하는 인증 기술과 절차를 적용하여, 접근을 요청하는 사용자/개체가 주장하는 신원이 실제와 일치함을 검증하도록 요구하는 통제입니다. 인증 강도를 자산 등급과 위험에 맞게 설정함으로써 자격증명의 탈취, 추측, 재사용을 통한 비인가 접근 위험을 줄이는 것을 목적으로 합니다.

## 주요 확인사항

1. 접근 대상 정보/시스템의 중요도와 위험에 따라 인증 수단(지식/소유/생체 기반)을 차등 적용하고 있는가?
2. 특권 계정, 원격 접근, 중요 시스템 접근 등 고위험 접근에 다중요소 인증(MFA)을 적용하고 있는가?
3. 로그인 실패 횟수를 제한하고(계정 잠금/지연/CAPTCHA 등), 실패 메시지가 어떤 자격증명이 틀렸는지 노출하지 않도록 설계되어 있는가?
4. 비밀번호/토큰 등 자격증명을 전송 및 저장 시 안전하게 보호(전송 암호화, 저장 시 해시/솔트)하고 있는가?
5. 안전한 로그온 절차(입력값 마스킹, 세션 시간초과, 접속 경고 문구 등)를 구성하고 인증 이벤트를 기록 및 모니터링하는가?

## 이행 지침

- 자산 등급과 위험 평가 결과에 따라 인증 요소를 선정하고, 고위험 접근에는 다중요소 인증을 적용합니다.
- 비밀번호는 입력 시 화면에 노출하지 않고, 전송 구간은 TLS 등으로 암호화하며 평문 전송을 금지합니다.
- 자격증명은 솔트를 포함한 강력한 해시로 저장하고, 평문 또는 취약한 알고리즘(MD5/SHA-1 등)에 의한 저장을 금지합니다.
- 반복된 로그인 실패에 대해 잠금/지연/알림을 적용하고, 오류 메시지에는 아이디/비밀번호 중 무엇이 틀렸는지 표시하지 않습니다.
- 유휴 세션을 자동 종료하고, 중요 작업 수행 시 재인증을 요구하며, 접속 위치/기기/행위 등 상황 기반의 적응형 인증을 검토합니다.
- 피싱/재전송 공격에 강한 인증 수단(FIDO2, 인증서 기반 등)을 도입하고, 인증 정보 관리(A.5.17)와 연계합니다.

## 관련 통제 및 속성

- ISO 27001 본문 연계: 6.1(위험 대응), 8.1(운영 계획 및 통제)
- 인접 Annex A: A.5.15(접근 통제), A.5.16(신원 관리), A.5.17(인증 정보), A.5.18(접근권한), A.8.2(특권 접근권한), A.8.3(정보 접근 제한)
- ISMS-P 대응: 2.5.3 사용자 인증
- 2013 대응: A.9.4.2(안전한 로그온 절차)

## 증적자료

- 등급/위험별 인증 수단을 규정한 인증 정책/표준
- 특권/원격/중요 접근에 대한 다중요소 인증 설정 화면
- 계정 잠금/로그인 시도 제한 설정 화면
- 자격증명 저장 방식(해시/솔트) 및 전송 구간 암호화 설정 근거
- 접속 경고 문구, 세션 시간초과 설정 화면
- 인증 성공/실패 로그 및 이상 인증 모니터링/알림 기록

## 부적합 사례

- 관리자 콘솔/특권 계정에 단일 비밀번호만으로 접근이 가능하고 다중요소 인증이 적용되지 않은 경우
- 로그인 오류 메시지가 아이디 또는 비밀번호 중 무엇이 틀렸는지 구체적으로 노출하는 경우
- 계정 잠금/시도 제한이 없어 무제한 로그인 시도(무차별 대입)가 가능한 경우
- 자격증명이 평문(HTTP)으로 전송되거나 평문 또는 취약한 해시로 저장된 경우
- 여러 사용자가 하나의 특권 계정을 공유하여 개별 인증이 이루어지지 않는 경우
