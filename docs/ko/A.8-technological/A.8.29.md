# A.8.29 개발 및 인수 단계 보안 시험 (Security testing in development and acceptance)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.8 기술적 통제 (Technological) |
| 통제 | A.8.29 개발 및 인수 단계 보안 시험 |
| 통제 유형(참고) | 예방적 / 탐지적 (Preventive / Detective) |
| 보안 속성(참고) | 기밀성 / 무결성 / 가용성 |
| ISMS-P 대응 | 2.8.2 보안 요구사항 검토 및 시험 |
| 2013 대응 | A.14.2.8, A.14.2.9 |

## 통제 목적

개발하거나 도입하는 시스템/애플리케이션이 운영 환경에 반영되기 전에 정의된 보안 요구사항을 실제로 충족하는지 시험을 통해 확인하기 위한 통제입니다. 보안 시험은 개발 생명주기 전반에 걸쳐 계획적으로 수행되어야 하며, 인수(운영 이관/구매 도입) 단계에서는 사전에 정한 합격 기준에 따라 결과를 검증하고 승인해야 합니다. 이를 통해 취약점이 운영 환경에 유입되기 전에 발견/제거되고, 시험 결과가 릴리스 승인의 근거로 기능하도록 보장합니다.

## 주요 확인사항

1. 개발/도입 대상에 대해 보안 시험의 범위, 방법, 시점, 책임자를 사전에 계획하고 문서화하는가?
2. 시험이 A.8.26에서 정의한 보안 요구사항을 기준으로 설계되고, 요구사항과 시험 항목 간 추적성이 확보되는가?
3. 정적/동적 분석, 취약점 점검, 침투 시험 등 시스템 위험 수준에 맞는 보안 시험 기법이 적용되는가?
4. 인수(운영 이관/구매 제품 도입) 단계에서 합격 기준을 사전에 정하고, 그 기준에 따라 시험 결과를 검증하여 승인하는가?
5. 발견된 취약점/결함이 위험도에 따라 조치/재시험되고, 잔여 위험이 릴리스 승인 시 반영되는가?
6. 보안 시험 환경과 데이터가 실제 운영 데이터를 그대로 사용하지 않도록 통제되며, 시험 기록이 보존되는가?

## 이행 지침

- 개발 생명주기(A.8.25)와 연계하여 보안 시험 계획을 수립하고, 시스템의 위험 등급/노출 환경에 따라 시험 범위와 깊이(코드 검토, 취약점 점검, 침투 시험 등)를 차등 적용합니다.
- A.8.26의 보안 요구사항 및 A.8.27의 아키텍처/엔지니어링 원칙을 시험 케이스로 구체화하고, 요구사항 ID와 시험 항목을 연결하여 누락 없이 검증되도록 추적성을 확보합니다.
- 개발 단계에서는 정적 분석(SAST), 소프트웨어 구성 분석(SCA/의존성 취약점 점검), 시크릿 스캔 등을 CI 파이프라인에 통합해 조기에 결함을 탐지하고, 실행 환경에 대한 동적 분석(DAST)/퍼징을 병행합니다.
- 인수 단계에서는 합격/불합격 기준(허용 가능한 잔여 위험, 심각도별 조치 기준)을 사전에 정의하고, 인수 시험(보안 구성 점검, 침투 시험 결과 확인)을 통과한 경우에만 운영 이관을 승인합니다.
- 구매/외부 도입(SaaS 포함) 제품은 공급자가 제출한 보안 시험/인증 결과를 검토하고, 필요 시 독립적인 취약점 점검을 수행하여 도입 요건 충족 여부를 확인합니다(A.8.30 연계).
- 시험 데이터는 실제 운영/개인정보를 그대로 사용하지 않도록 가명/합성 데이터를 활용하고(A.8.31/A.8.33 연계), 발견된 취약점의 조치 및 재시험 결과, 승인 내역을 문서로 보존합니다.

## 관련 통제 및 속성

- ISO 27001 본문 연계: 8.1(운영 계획 및 통제), 9.1(모니터링, 측정, 분석 및 평가), 6.1(위험 및 기회 대응)
- 인접 Annex A: A.8.25(안전한 개발 생명주기), A.8.26(애플리케이션 보안 요구사항), A.8.27(안전한 시스템 아키텍처 및 엔지니어링 원칙), A.8.28(안전한 코딩), A.8.30(외주 개발), A.8.31(개발/시험/운영 환경 분리), A.8.33(시험 정보), A.8.8(기술적 취약점 관리)
- ISMS-P 대응: 2.8.2 보안 요구사항 검토 및 시험 (연계: 2.8.1 보안 요구사항 정의, 2.8.3 시험과 운영 환경 분리, 2.8.4 시험 데이터 보안, 2.8.6 운영환경 이관, 2.11.2 취약점 점검 및 조치)
- 2013 대응: A.14.2.8(시스템 보안 시험), A.14.2.9(시스템 인수 시험)

## 증적자료

- 보안 시험 계획서(범위/방법/시점/책임자) 및 요구사항과 시험 항목의 추적성 매트릭스
- 정적/동적 분석, 취약점 점검, 침투 시험 결과 보고서 및 CI 파이프라인 보안 검사 로그
- 인수 시험 합격 기준 및 인수/운영 이관 승인 기록
- 발견 취약점 조치 내역, 재시험 결과, 잔여 위험 수용 승인 문서
- 구매/도입 제품에 대한 공급자 보안 시험/인증 결과 검토 및 도입 승인 문서
- 시험 데이터 통제(가명/합성 데이터 사용) 및 시험 기록 보존 내역

## 부적합 사례

- 보안 시험 계획 없이 기능 시험만 수행하고 운영에 이관한 경우
- 보안 요구사항과 연계된 시험 항목이 없어 요구사항이 검증되지 않은 채 릴리스된 경우
- 취약점 점검/침투 시험에서 발견된 고위험 결함이 조치/재시험 없이 운영에 반영된 경우
- 인수(운영 이관) 단계의 합격 기준이 사전에 정의되지 않아 승인 판단이 자의적으로 이루어진 경우
- 구매/외부 도입 제품의 보안 시험 결과를 검토하지 않고 도입한 경우
- 보안 시험에 실제 운영/개인정보 데이터를 통제 없이 사용한 경우
