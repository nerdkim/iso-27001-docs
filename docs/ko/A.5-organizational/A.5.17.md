# A.5.17 인증 정보 (Authentication information)

| 구분 | 내용 |
|---|---|

| 통제 유형(참고) | 예방적 |

## 통제 목적
인증 정보(비밀번호, PIN, 토큰 시크릿, 인증서 개인키, API 키 등)는 사용자나 시스템의 신원을 증명하는 핵심 비밀이므로, 발급부터 사용, 갱신, 폐기까지 전 생애주기에 걸쳐 안전하게 배포/보관/관리되어야 합니다. 이 통제는 인증 정보가 유출되거나 추측/재사용되어 무단 접근으로 이어지지 않도록 조직과 사용자 양쪽의 책임과 관리 절차를 정립할 것을 요구합니다. 인증 정보의 품질(복잡도/길이/재사용 제한)과 안전한 저장/전송을 함께 보장하는 것이 핵심입니다.

## 주요 확인사항
1. 신규 사용자나 시스템에 인증 정보를 최초 배포할 때 본인 확인 및 안전한 전달 절차가 정의되어 있는가?
2. 초기/임시 비밀번호는 유효기간을 짧게 두고 최초 로그인 시 강제로 변경하도록 설정되어 있는가?
3. 비밀번호 복잡도, 최소 길이, 재사용 제한, 유효기간 등 인증 정보 품질 기준이 정책으로 정의되고 시스템에 실제 적용되는가?
4. 인증 정보는 평문이 아닌 안전한 해시/암호화 형태로 저장되고, 전송 구간에서 암호화되는가?
5. 사용자가 인증 정보를 안전하게 관리하도록(공유 금지, 기록 금지, 개인 재사용 금지 등) 책임을 고지하고 서약을 받는가?
6. 인증 정보 유출/노출이 의심될 때 즉시 재설정하는 절차와 기본(default) 인증 정보 변경 절차가 마련되어 있는가?

## 이행 지침
- 인증 정보 유형별(사용자 비밀번호, 서비스 계정 시크릿, 암호키, 인증서 등) 발급/전달/보관/폐기 절차를 문서화하고 책임자를 지정합니다.
- 초기/임시 인증 정보는 유효기간을 짧게 두고 안전한 채널로 전달하며, 최초 사용 시 변경을 강제합니다.
- 비밀번호는 솔트를 적용한 강력한 단방향 해시로 저장하여 관리자도 평문을 확인할 수 없도록 하고, 전송 구간은 암호화(TLS 등)합니다.
- 비밀번호 정책(최소 길이, 복잡도 또는 패스프레이즈 허용, 유출 비밀번호 차단, 재사용 이력 제한, 계정 잠금)을 인증 시스템에 적용하고 다중인증(MFA)을 병행합니다.
- 시스템/서비스 계정의 하드코딩된 크리덴셜을 제거하고 비밀 관리 솔루션(secrets vault)으로 중앙 관리하며 주기적으로 교체합니다.
- 사용자에게 인증 정보 공유 금지, 피싱 대응, 개인용/업무용 재사용 금지 등 사용 책임을 교육하고 서약을 받습니다.

- 인접 Annex A: A.5.15 접근통제, A.5.16 신원 관리, A.5.18 접근권한, A.8.2 특권 접근권한, A.8.5 보안 인증
- ISMS-P 대응: 2.5.4 비밀번호 관리 (관련: 2.5.3 사용자 인증)
- 2013 대응: A.9.2.4, A.9.3.1, A.9.4.3

## 증적자료
- 인증 정보 관리 정책/절차서 (발급, 전달, 저장, 폐기 기준 포함)
- 비밀번호 정책 설정 화면 (복잡도, 최소 길이, 유효기간, 재사용 제한, 계정 잠금)
- 최초 로그인 시 비밀번호 강제 변경 설정 증적
- 비밀번호 저장 방식(해시/솔트) 확인 자료 및 전송 구간 암호화 설정
- 비밀 관리 솔루션(vault) 운영 및 시크릿 교체 이력
- 사용자 보안 서약서 및 인증 정보 취급 교육 기록

## 부적합 사례
- 신규 계정 초기 비밀번호가 전 사용자 동일 값으로 부여되고 최초 변경이 강제되지 않음
- 데이터베이스에 사용자 비밀번호가 평문 또는 단순 인코딩(base64) 상태로 저장됨
- 애플리케이션 소스코드/설정 파일에 DB 접속 비밀번호가 하드코딩되어 형상관리에 커밋됨
- 관리자 화면에서 사용자 비밀번호를 평문으로 조회할 수 있음
- 비밀번호 유효기간/복잡도 정책이 문서에는 있으나 실제 시스템에는 미적용됨
- 인증 정보 유출 의심 사고 이후에도 재설정이 이루어지지 않음
