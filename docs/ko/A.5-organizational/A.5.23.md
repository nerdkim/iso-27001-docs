# A.5.23 클라우드 서비스 이용 정보보안 (Information security for use of cloud services)

| 구분 | 내용 |
|---|---|
| 표준 | ISO/IEC 27001:2022 Annex A |
| 테마 | A.5 조직적 통제 (Organizational controls) |
| 통제 | A.5.23 클라우드 서비스 이용 정보보안 |
| 통제 유형(참고) | 예방적 |
| 보안 속성(참고) | 기밀성/무결성/가용성 |
| ISMS-P 대응 | 2.10.2 클라우드 보안 |
| 2013 대응 | 2022 신규 |

## 통제 목적
클라우드 서비스의 도입/이용/전환/종료 전 과정에서 조직의 보안 요구사항을 정의하고 이행하기 위한 통제입니다. 클라우드는 책임공유 모델에 따라 통제 지점이 제공자와 이용자로 나뉘므로, 이용자가 담당해야 할 보안 책임을 계약, 구성, 모니터링을 통해 빠짐없이 수행하는 것이 핵심입니다. 승인받지 않은 클라우드 사용을 통제하고, 종료/전환 시에도 데이터를 안전하게 회수/파기하여 조직이 클라우드 위험을 관리 범위 안에서 다루는 것을 목적으로 합니다.

## 주요 확인사항
1. 클라우드 서비스 도입 시 보안 요구사항과 이용 기준을 정의하고 승인 절차를 거치는가?
2. 서비스 유형(IaaS/PaaS/SaaS)별 책임공유 모델에 따라 제공자와 이용자의 보안 책임 경계를 문서화하였는가?
3. 클라우드 계정 및 구성(권한, 네트워크, 암호화, 로깅)에 대한 보안 기준을 수립하고 준수 여부를 점검하는가?
4. 클라우드 제공자의 보안 수준(인증, SLA, 사고 통지, 데이터 저장 위치)을 계약 전에 평가하고 계약에 반영하는가?
5. 클라우드 서비스 이용 종료/전환 시 데이터 회수 및 파기, 계정/권한 회수 절차를 마련하였는가?

## 이행 지침
- 클라우드 도입/이용 정책을 수립하고, 승인받지 않은 클라우드(섀도 IT) 사용을 식별/차단하는 절차를 운영한다.
- 서비스 유형별 책임공유 매트릭스를 작성하여 계정관리, 데이터 암호화, 네트워크 통제, 로그 수집 등 이용자 책임 항목을 명확히 한다.
- 클라우드 구성 보안 기준을 정의하고, 공개 스토리지 노출, 과도한 권한 부여, 미암호화 등 위험 구성을 주기적으로 점검한다.
- 계약 및 SLA에 데이터 저장 위치/국외이전, 사고 통지 시한, 감사 권한, 종료 시 데이터 반환/파기 조항을 명시한다.
- 클라우드 관리자 계정에 다중인증과 최소권한을 적용하고 관리 행위를 로깅/모니터링한다.
- 종료/전환 계획(exit plan)을 사전에 마련하여 데이터 이동성과 특정 제공자 종속(lock-in) 위험을 관리한다.

## 관련 통제 및 속성
- ISO 27001 본문 연계: 6.1 위험평가 및 대응, 8.1 운영 계획 및 통제
- 인접 Annex A: A.5.19 공급자 관계 정보보안, A.5.20 공급자 계약 내 정보보안, A.5.21 ICT 공급망 관리, A.5.22 공급자 서비스 모니터링/검토/변경관리
- ISMS-P 대응: 2.10.2 클라우드 보안
- 2013 대응: 2022 신규

## 증적자료
- 클라우드 도입/이용 정책 및 도입 승인 기록
- 서비스 유형별 책임공유 매트릭스
- 클라우드 계약서/SLA (데이터 저장 위치, 사고 통지, 종료 조항 포함)
- 클라우드 구성 점검 보고서 및 위험 구성 조치 내역
- 클라우드 관리자 계정 권한/다중인증 설정 내역 및 접근 로그
- 서비스 종료/전환 시 데이터 반환/파기 확인서

## 부적합 사례
- 부서가 승인 없이 SaaS를 도입해 고객정보를 저장하고 있으나 조직 차원의 관리 대상에서 누락됨
- 책임공유 모델을 이해하지 못해 이용자 책임인 데이터 암호화/접근통제를 제공자가 수행할 것으로 오인함
- 클라우드 스토리지가 공개(public) 상태로 구성되어 인터넷에 노출됨
- 계약서에 데이터 저장 위치와 종료 시 데이터 파기 조항이 없어 이전/파기 근거가 불명확함
- 클라우드 관리 콘솔 계정에 다중인증이 적용되지 않고 관리 행위에 대한 접근 로그가 수집되지 않음
